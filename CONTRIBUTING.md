# Совместная работа

Основной файл приложения — `main.py`. Инструкции установки находятся в [README.md](README.md).

## Как вносить изменения

1. Получите актуальную версию ветки `main`.
2. Создайте отдельную ветку с понятным именем, например `fix/portfolio-metals`.
3. Внесите изменения и проверьте затронутые сценарии.
4. Откройте Pull Request: опишите проблему, изменение поведения и выполненные проверки.
5. После просмотра изменений объедините ветку с `main`.

Не добавляйте в репозиторий виртуальное окружение, пароли и личные данные. Для оформления и документации достаточно проверки ссылок, команд и соответствия описания исходному коду.

## Проверка перед демонстрацией

Это список предстоящих проверок, а не отчёт об их успешном выполнении.

- [ ] Установить зависимости в чистое окружение и открыть приложение.
- [ ] Проверить загрузку валют и четырёх металлов; сверить значения и даты с ответами ЦБ.
- [ ] Проверить валюту с номиналом больше единицы: цена должна быть приведена к одной единице.
- [ ] Сверить конвертацию вручную. Пример с условными данными: при 90 ₽/USD сумма 100 USD равна 9000 ₽; при 9000 ₽/г золота — одному грамму.
- [ ] Проверить портфель на условных данных: 100 USD по 90 ₽ и 2 г золота по 9000 ₽ дают 27 000 ₽.
- [ ] Проверить дневное изменение: если прежние цены были 89 ₽/USD и 8900 ₽/г, изменение такого портфеля должно быть +300 ₽. Текущая версия не учитывает вклад металла; этот пункт требует исправления кода.
- [ ] Проверить график для валюты и металла, каждый период и сравнение с предыдущим.
- [ ] Экспортировать PNG и CSV, открыть оба файла и сверить данные.
- [ ] Проверить поведение при недоступности сети и при некорректном вводе.
- [ ] Проверить пороги уведомлений и горячие клавиши.
- [ ] Подготовить демонстрацию: карточка → график → конвертер → портфель → экспорт.

В отчёте о проверке укажите ОС, версию Python, версии зависимостей, дату, выполненные сценарии и обнаруженные ошибки. Не отмечайте незапущенные сценарии как пройденные.
